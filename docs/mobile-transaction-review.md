# Mobile transactions and review

- iOS and Android load the next transaction page automatically near the end of the list. Pull-to-refresh starts at page one and supersedes any older request. Pagination completions cannot release a newer request's lock or append data from an old Profile/filter.
- Home's Things to Review navigates directly to the pending transaction list in the selected currency. Each entry from Home resets previous searches and filters. Transaction review is not repeated in Next Steps.
- Home and the native list use the same actionable review reasons. A pending/suggested status alone is not a warning. The native row endpoint enriches only the returned page and does not calculate the entire ledger's financial summary.
- Same-day, same-amount transfers are independent occurrences unless specific matching source evidence identifies an overlap. Opposite directions, separate accounts, different currencies and conflicting references cannot be combined by the bank-overlap matcher. Exact source/provider identities retain idempotent one-to-one matching.
- A possible bank overlap is included in financial totals while awaiting review. Legacy automatic exclusions with the bank-overlap reason are included by read-only projection; confirmed records and explicit manual exclusions remain unchanged. True transfers retain the existing transfer accounting rules, so inclusion does not turn a transfer into income or spending.
- Keep resolves actionable review flags without changing the amount, date, merchant, category, source payload or tags. Delete uses the existing audited soft-deletion flow. Bulk Keep skips confirmed/edited rows, is atomic, checks for concurrent changes, and audits each resolved row. Bulk Delete affects all selected rows only after confirmation.
- Holding a row starts selection. Tapping other rows toggles them. Keep applies only to selected rows requiring review; Delete applies to every selected row. Users can select loaded rows and continue scrolling to add more, up to 500.
- Recently cached Home data remains available during background revalidation. Cold-start snapshot restoration prioritizes Home, retains it for up to 30 minutes, and remains scoped to the authorized user/Profile/currency. Writes invalidate snapshots. Currency choices are grouped in PostgreSQL instead of transferring the full ledger to deduplicate currencies in the application.

Verification includes real PostgreSQL coverage for a 57-row review queue, both pages and exhaustion, Home/list count parity, mixed selections, audit records, explicit exclusions, confirmed-data preservation and Profile isolation. Functional native pagination checks cover refresh/append races; offline checks cover cache age, authorization and invalidation. Browser preview checks use isolated fictional data.
