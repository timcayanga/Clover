# Team agent execution

Team → Distribution lead (or another role) → Open role & briefs → Save brief → Start assignment opens a permanent `/team/assignments/<UUID>` page. Each role executes only when the verified owner starts it. Review actions approve the exact saved result or create a separate revision with feedback; they never publish or delegate. The creator can return copy, visual directions, scripts, or one generated image when the owner selects that deliverable.

## Execution and ownership

- Uses the existing server-side `OPENAI_API_KEY` and Responses API background mode. Default model: `gpt-5.4-mini`; override with `CLOVER_TEAM_AGENT_MODEL` only after checking background, reasoning, and web-search compatibility. `CLOVER_TEAM_AGENTS_ENABLED=false` pauses new starts without preventing existing runs from finishing.
- Only the community researcher receives `web_search`, capped at three tool calls. No role receives customer-data, social-account, messaging, publishing, shell, or financial tools. Brief, saved standing instructions, and revision context are the only owner data sent to OpenAI. Outputs remain unapproved suggestions.
- Provider responses use `store: true` so polling can recover after closing the browser. This is ordinary Responses storage, not a zero-data-retention design; see OpenAI background-mode/data-control documentation. Do not put secrets or customer records in briefs.
- Reserves the run UUID before a paid request, snapshots its instructions, and serializes owner starts with a PostgreSQL transaction advisory lock. Unique trigger keys deduplicate repeated clicks. A revision has at most one child. Retries preserve the failed attempt's original prompt and feedback.
- Per owner: maximum three active assignments and twenty starts per UTC day, including failed attempts and retries. A run permits at most 6,000 output tokens. Ambiguous POST failures are recorded without automatic paid retries; the UI explains possible usage.
- OpenAI continues generating while the browser is closed. Opening the result page polls and persists completed output immediately. `/api/cron/team-assignments` also polls daily at 03:00 UTC after production promotion (the current Vercel Hobby plan permits only daily schedules), authenticated with `CRON_SECRET`. Provider IDs remain server-side. Poll claims last 150 seconds, covering the bounded retrieve/cancel/retrieve sequence (each provider request has a twenty-five-second timeout; private image persistence has bounded storage requests). Terminal results cannot be overwritten by late polls.
- Cancellation asks the provider to stop; usage already incurred may still be billed. If completion wins the race, the completed proposal is saved for review. A start interrupted before receiving a provider ID becomes failed after two minutes; it cannot be safely reattached automatically.
- Run and event tables are private, RLS-enabled, and inaccessible to Supabase public API roles. Owner authentication and same-origin mutation checks apply to every Team API. Approval is serialized with revision creation; the old result remains intact but is marked changes requested.
- Results show usage and estimated USD charges at uncached list prices ($0.75/M input, $4.50/M output, $0.01/search for the default model); unknown model overrides show usage without fabricated pricing. Prices are estimates, not billing records.

This exercises real routes/transactions with test-only Clerk and OpenAI adapters: auth/origin/payload checks, concurrent duplicate starts, limits, snapshots, completion and reload, revisions and approval invalidation, cancellation, ambiguous failure, background recovery, safe citations, tool permissions, and RLS. ## Complete owner workflow

- **Assignments** includes saved briefs ready to start and lists the latest run for each started brief, with search and filters for working, needs review, approved, and needs attention. The overview and **Approvals** include pending agent results alongside content drafts. Visible workspaces check progress every 15 seconds and on focus; **Refresh progress** and **Refresh assignment** provide explicit recovery controls. Hidden tabs pause polling. This does not change the daily unattended recovery schedule.
- Results render a safe Markdown subset (headings, lists, bold, code, HTTPS links and source citations). Raw HTML is escaped and remote images are not embedded. **Copy result** preserves the original text.
- Approved results offer **Save follow-up brief**. The owner chooses the receiving role and writes its next task. The next agent receives a snapshot of the approved source as context only when the owner separately starts the saved brief. A withdrawn source approval prevents new execution against it.
- **Create content draft** takes owner-selected copy, title, channel and format into the content board. It starts as an unapproved Draft and can receive images/video attachments and its own review. Long outputs require choosing an excerpt within the existing 6,000-character draft limit. A generated image is automatically attached to its content draft. This does not connect publishing platforms.
- Both transitions preserve a source-assignment link and audit event, deduplicate repeated submissions, and use the studio revision check to avoid overwriting other edits. Source links cannot be forged or changed through ordinary studio saves.
- A different concurrent revision is rejected with an explicit conflict while preserving the owner's typed feedback. Repeated identical revision requests remain idempotent. Cancellation retrieves provider state first, saving a completion that won the race; interrupted/expired runs receive failure audit events.

## Image production and manual publishing

- Content Creator saved briefs offer **Copy, plan, or video script** (default) and **Generate one image**. Image runs use the existing background Responses flow, the same text model, and a forced single `image_generation` tool call with `gpt-image-1.5`, medium quality, 1024×1024 PNG. Maximum five image starts per UTC day including revisions/retries; the shared concurrency/daily limits still apply. Switching mode after a start cannot duplicate generation.
- Provider IDs are persisted before saving images. A storage outage retries retrieval/storage of the same result, never a new paid generation. Media uses the run UUID, private R2 storage, immutable first-write bytes, owner-only signed reads/downloads, and the existing Team media table. No database migration is needed. Raw image base64 never enters assignment JSON or database records.
- Images are previewed beside the result and require owner approval. Revisions generate a new image using the brief and feedback; they are not pixel edits of the prior image. Image charges are not included in the text-token estimate, so no misleading total estimate is shown.
- Approved content drafts offer **Copy approved caption** and **Download approved media** for manual publishing. Any edit invalidates approval before those controls return. No social account has been connected and no publishing action is automated.
- Image drafts offer **Create motion clip**: a browser-rendered, silent six-second 1080×1080 video with a gentle zoom (MP4 where supported, otherwise WebM). It replaces the draft attachment only after rendering/upload succeeds; saving invalidates approval and preserves the old image in version history. Chrome-compatible MediaRecorder/canvas capture support is required, and the tab must remain open. This is animated artwork, not AI scene generation.
- Video scripts and MP4/WebM uploads continue to work. OpenAI's Sora models/Videos API shut down September 24, 2026 with no one-to-one replacement. Video generation requires choosing and configuring another provider; do not expose a nonworking Sora action.
- Admin navigation no longer forces prefetch of every expensive aggregate page, reducing speculative database fan-out. This addresses a contributor to connection-pool timeouts, not a guarantee against infrastructure outages.

References: [Image tool](https://developers.openai.com/api/docs/guides/tools-image-generation), [Sora shutdown](https://developers.openai.com/api/docs/guides/video-generation).

## Final execution controls

- **Withdraw approval** returns a completed result to pending review without starting or charging for another generation. It blocks new handoffs and new follow-up starts from that source. Existing drafts/runs retain their independent history. Reapproval is explicit and all decisions are audited under the same owner lock.
- Missing or malformed generated images end in a failed, retryable run, preserving any returned text and usage. Temporary storage failures keep the provider ID and report delayed persistence; refreshing retrieves the existing result rather than generating again.
- Motion rendering prefers MP4, falls back to supported WebM, and bounds image decoding/recording waits so the UI recovers if the browser cannot finish.
- Direct social publishing is not configured: no Facebook/Instagram/LinkedIn/TikTok/YouTube publishing credentials were found in the production environment inventory during the September 28 audit. Activation requires a selected Clover account, platform application credentials, and owner OAuth authorization. No social passwords should be stored in Clover. Full generative scene video likewise needs a separately selected provider; image-to-motion export is operational.
